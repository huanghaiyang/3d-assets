# 3D 舞台：多角色动作序列编排

## Context

现有应用有两个页面（工作台 / 动画预览），动画预览页一次只能看一个 FBX、一次只能播一个片段。Kimodo 生成的文生动作也只能在 `KimodoPreview.vue` 里以「点 + 线」的形式单独预览，无法与 Mixamo 动画库的现成片段组合使用。

需要新增第三个工作区「3D 舞台」，把 Kimodo 生成的动作和 Mixamo 动画库的片段都当作可编排的素材：**多个角色同台，每个角色各自串一条动作序列，自由摆放位置，相邻片段之间做到无突变的衔接。**

核心难点在于两种动画表示不统一：Mixamo FBX 天然产出 `THREE.AnimationClip`，而 Kimodo 输出的是原始 f32 骨骼流（`root_positions.f32 [FRAMES,3]` + `local_rotations_xyzw.f32 [FRAMES,30,4]`），现有实现是逐帧直接写关节四元数。舞台引擎必须先把两者统一到同一套 `AnimationClip` + `AnimationMixer` 模型上，才能做权重混合。

## 范围

**做：**
- 新增「舞台」页签与独立页面
- 多角色（Actor）同台，每个角色一条独立序列
- 角色两种形态：Mixamo FBX 角色（有网格蒙皮）、Soma 骨架角色（点+线，复用 KimodoPreview 的渲染风格）
- 片段来源：Mixamo 动画库 FBX clip、Kimodo 生成动作（经 retarget 后挂到 FBX 角色）
- 序列编辑：增删片段、调整顺序、裁剪起止、设置每段与下一段的重叠时长
- 播放：全局时间轴、拖动进度、循环、倍速
- 自由摆放：在场景里拖 x/z + 旋转 Y，也可在检查器里输数值
- 三层衔接：crossfade 权重混合、根位移对齐、脚部锁定防滑步
- 舞台文档服务端持久化

**不做（V1 之外）：**
- 多角色之间的交互约束（IK 手部抓取、注视约束）——上一版需求里提的 constraints，本次不做
- 片段的曲线编辑器 / 关键帧编辑
- 导出为 FBX / glTF（后续可加）

## 架构

### 统一到 AnimationMixer

所有片段一律转成 `THREE.AnimationClip`，角色一律持有 `AnimationMixer`。引擎不关心底层是 FBX 还是 Soma。

| 片段来源 | 转换路径 |
| --- | --- |
| Mixamo FBX 内嵌 clip | `FBXLoader` 直接得到 `AnimationClip` |
| Kimodo → Mixamo 角色 | `GET /api/kimodo/import/:id` 取 `fbx-animation-data` JSON → 轨道转 `QuaternionKeyframeTrack` |
| Kimodo → Soma 角色 | `GET /api/kimodo/skeleton` 取 30 关节定义 + `/root.f32` + `/rotations.f32` → 直接构造 30 条 Quaternion 轨 + Hips 位置轨 |

关键复用：[FbxPlayer.applyAnimationData()](file:///d:/sgames/3d-desing/apps/web/src/viewer/FbxPlayer.ts#L1165-L1221) 已经实现了 `fbx-animation-data` → `AnimationClip` 的完整转换，包括 `boneNameMap` 骨骼名别名对齐（`bone.name` / `sanitizeNodeName` / `cleanBoneLabel`）。**把这段纯转换逻辑抽到新文件 `viewer/stage/clipFromAnimationData.ts`，让 `FbxPlayer.applyAnimationData` 改为委托调用**，保证单一事实来源、避免两份实现漂移。这是一次机械提取，行为不变。

### 片段与角色的兼容规则

不同骨架不能混用，UI 层直接按角色类型过滤可选片段：

- **FBX 角色**：可选 Mixamo FBX clip、Kimodo 动作（走 retarget）
- **Soma 角色**：只能选 Kimodo 动作（原生 30 关节）

## 数据模型

```ts
// viewer/stage/StageTypes.ts
type ActorKind = 'fbx' | 'soma';

interface StageActorDef {
  id: string;
  name: string;
  kind: ActorKind;
  /** kind=fbx 时为 FBX 路径；kind=soma 时忽略 */
  modelPath?: string;
  transform: { x: number; z: number; yaw: number };
}

interface SegmentDef {
  id: string;
  actorId: string;
  source:
    | { kind: 'fbx-clip'; fbxPath: string; clipName: string }
    | { kind: 'kimodo'; animationId: string };
  trimStart: number;   // 秒，片段内裁剪起点
  trimEnd: number;     // 秒，片段内裁剪终点
  start?: number;      // 全局时间轴起点，秒；缺省表示紧跟上一段结束
  color?: string;      // 自定义标识色 #rrggbb；缺省按序号沿色相环自动生成
}

interface StageDoc {
  id: string; name: string;
  actors: StageActorDef[];
  segments: SegmentDef[];   // 同一 actorId 的片段按数组顺序构成该角色序列
  loop: boolean;
  updatedAt: string;
}
```

## 播放引擎关键算法

### 1. 时间轴折算（`SequenceTimeline.ts`，纯函数）

```
build(segs):
  for i:
    len[i] = trimEnd - trimStart
    gs[i]  = start[i] ?? (i ? ge[i-1] : 0)             // 显式起点优先，否则首尾相接
    b[i]   = i ? max(0, min(ge[i-1] - gs[i], len[i], len[i-1])) : 0  // 重叠由实际摆放推导
    ge[i]  = gs[i] + len[i]
  total = max(ge[*])

resolve(t) -> [{seg, localTime, weight}]:
  t = clamp(t, 0, total)
  i = 最后一个 gs[i] <= t 的序号
  if i > 0 && t < gs[i] + b[i]:          // 处于交叉窗口
    e = smoothstep((t - gs[i]) / b[i])
    return [{seg: i-1, local: t - gs[i-1],   weight: 1-e},
            {seg: i,   local: t - gs[i],     weight: e}]
  return [{seg: i, local: t - gs[i], weight: 1}]
```

`action.time = trimStart + localTime`，超出 `[0, len]` 时 clamp。

### 2. 驱动方式：手动权重（不用 crossFadeTo）

`AnimationMixer` 的 `fadeIn` / `crossFadeTo` 依赖 `mixer.time` 推进，而我们要支持**拖动进度条 scrub**，所以强制用「每帧手动写 time + weight」：

- action 只创建一次：`mixer.clipAction(clip)`
- 初始化 `reset(); play(); setLoop(LoopRepeat, Infinity); paused = true`
- 每帧：`action.time = x`、`action.setEffectiveWeight(w)`、`action.enabled = true`
- 每帧末尾 `mixer.update(0)` 强制求值写骨骼

坑位（必须遵守）：
- `paused=true` 只冻结 `timeScale`，不阻止写骨骼；`update(0)` 仍会走 `_updateWeight` + 绑定写入
- 不要用 `fadeIn/fadeOut/crossFadeTo`，它们会留下 `_weightInterpolant`、且 `mixer.time` 不前进导致卡死
- 同一 clip 不能建两个不同 time 的 action（`clipAction` 按 `clip.uuid` 缓存），需要同一片段在序列里出现两次时用 `clip.clone()`
- 不要每帧 `stop()` / `uncacheClip()`，会重置权重并抖动
- 每帧显式置 `enabled = true`（fade 结束后 three 会自动置 false）
- 权重和必须精确等于 1，否则 `PropertyMixer` 会用绑定姿态原值补足，导致手指/脚趾塌陷

### 3. 根位移对齐（`RootAlign.ts`）

不在运行时累加偏移（拖进度条会漂）。**建序列时预计算每个边界的角色基准变换 `T[i]`**：

```
以权重 1 分别采样：
  a = hipsActorLocal(clipA, trimEnd)        // 上一段结束时的髋部（相对角色根）
  b = hipsActorLocal(clipB, trimStart + b[i])

dYaw = wrapPi(yaw(b.q) - yaw(a.q))
off  = a.p - rotY(dYaw, b.p) ; off.y = 0
T[i] = { yaw: T[i-1].yaw + dYaw,
         pos: T[i-1].pos + rotY(T[i-1].yaw, off) }
```

运行时：交叉窗口内 `T(t) = lerp(T[i-1], T[i], wB)`；窗口结束后直接用常量 `T[i]`，**无累积漂移**。

角色实际位置 = `T(t).pos + rotY(T(t).yaw, 当前髋部 xz - 该段起始髋部 xz)`。
过渡窗口内 A/B 的根位移按 `1-wB : wB` 混合。

`inPlace`（已 `stripRootMotion`，髋部 xz 恒定）时 `off.xz = 0`，只保留 `dYaw`。

> 注意：放置位置（x/z/yaw）永远写 Actor 的 `root` Group，不要写承担归一化 scale/居中 的内部 model 容器。

### 4. 脚部锁定（`FootIK.ts`）

分两步，先低成本近似再上真 IK：

**第一步 · 支撑脚漂移补偿（约 30 行，随 V1 交付）**
交叉窗口内每帧对比支撑脚（脚踝世界高度最低、水平位移最小）在窗口起点的世界 xz 与当前 xz，把差值反加回 `actorRoot.position`。可消灭大部分滑步观感，且不碰骨骼。

**第二步 · 解析两骨 IK（V1.5）**
只在交叉窗口内、只对检测到的支撑脚做：
- 目标点 = 窗口起点脚踝世界 xz + `groundY`
- 腿长 `l1`（髋→膝）、`l2`（膝→踝）
- `d = clamp(|T-H|, ε, 0.999*(l1+l2))`
- 余弦定理求膝弯角，大腿用 `quaternion.setFromUnitVectors` 对齐 `H→T`，小腿、脚依次求解
- 用 sin 曲线淡入淡出，避免窗口边缘跳变

**与 mixer 的冲突（关键）**：`PropertyMixer` 每帧都用「轨道值 + 绑定原值」重写局部 TRS，不继承上一帧。所以 IK 必须在 `mixer.update(0)` + `updateMatrixWorld()` **之后**写 `bone.quaternion`，且同一帧末尾不能再调 `mixer.update`，否则被覆盖。

## 验证

**引擎正确性（无 UI 也能验）**
- `SequenceTimeline.resolve()` 在任意时刻返回的权重之和恒等于 1（含首段、末段、blend 为 0 的硬切）
- 序列总时长 = `Σ len - Σ blend`，且拖动进度条到任意位置画面稳定、不抖动

**端到端**
1. `npm run build -w @h3d/web` + `npm run build -w @h3d/api` 通过
2. 启动 API（8788）与前端，切到「舞台」页
3. 添加一个 FBX 角色，从动画库挑 2–3 个片段入序列，设 overlap 0.3s，播放 → 观察过渡处无姿势跳变
4. 添加第二个角色（Soma 骨架），绑定一条 Kimodo 动作，摆到不同位置，两角色同时播放互不干扰
5. 拖动进度条来回 scrub → 画面跟随、角色位置不漂移
6. 开启「原地播放」的片段 → 根对齐退化为只对齐朝向，无侧向瞬移
7. 保存舞台 → 刷新页面重新载入 → 角色位置、序列、重叠时长全部还原

**性能**
- 两个 FBX 角色 + 各自 3 段序列同时播放，帧率不低于 30fps
- 引擎只保留当前片段附近的 action 为 enabled，避免全序列 action 每帧求值

## 风险与取舍

- **脚部 IK 是最大变量**。V1 先用支撑脚漂移补偿保证可用观感，解析两骨 IK 单列为第 6 步；若调试点 cloud 花费超出预期，第 6 步可独立延后，不影响前 5 步交付。
- **权重和必须严格归一**。跨骨架混播时权重不足 1 会让未覆盖的骨骼塌回绑定姿态，这是最容易被忽略的视觉 bug，`SequenceTimeline` 的纯函数测试要覆盖这一条。
- **Soma 与 Mixamo 骨架不可互换**。UI 层必须按角色类型过滤片段，否则会出现「关节名不匹配、track 被静默跳过」的空白动画。
- **不改动 `FbxPlayer` 的行为**。抽取转换器是机械操作，改动后需回归动画预览页，确认原有「新建动画 / 导入动画 JSON」功能不受影响。
